# thermal-depth-h200 — 열화상 깊이 추정이 다른 데이터에서도 되는가

열화상 한 장으로 깊이를 추정하는 모델을 MS2로 학습하고, 학습에 쓰지 않은 열화상 데이터(FIReStereo, ViViD)에서 그대로 평가한다. Aerodrone H200에서 돌리는 실행 묶음이다. 데이터와 가중치는 저장소에 없고 실행할 때 받는다.

## 동기

열화상 깊이 추정은 MS2 안에서는 이미 포화에 가깝다. 선행 논문 MonoTher-Depth(arXiv 2504.16127)의 표에서 MS2 test의 AbsRel은 방법에 따라 0.072–0.091이고, 같은 모델을 다른 데이터(ViViD 야외 밤)로 가져가면 0.153–0.174로 두 배가 된다. 다른 데이터에서 평가한 논문은 이 한 편뿐이고 대상도 한 곳이다.

그래서 먼저 두 가지를 확인한다.

1. 기준선(Depth Anything V2를 MS2 열화상으로 미세조정)이 MS2에서 선행 수치만큼 나오는가.
2. 그 모델이 다른 열화상 데이터에서 실제로 무너지는가. 무너지지 않는다면 주제를 다시 잡아야 한다.

여기에 추가 데이터 없이 해 볼 수 있는 방법 하나(무작위 톤매핑 증강)를 같은 작업에서 함께 돌린다. 깊이 정답이 없는 RGB-열화상 쌍에 의사 라벨을 붙이는 방법은 이 결과를 본 뒤에 다음 단계로 넣는다.

## 실험

| 팔 | 내용 |
|---|---|
| `base` | 기준선. Depth Anything V2 ViT-L을 MS2 열화상과 LiDAR 정답으로 미세조정한다. 증강은 좌우 뒤집기뿐이다 |
| `tone` | `base`에 무작위 톤매핑 증강을 더한다. 학습 때만 바뀌고 평가 입력은 `base`와 같다 |

모델과 학습 설정은 공식 Depth Anything V2 metric 학습(`metric_depth/train.py`)을 따른다.

| 항목 | 값 | 공식과 같은가 |
|---|---|---|
| 모델 | 공식 metric 판 DPT, 인코더 ViT-L. 상대 깊이 체크포인트에서 인코더만 싣고 헤드는 새로 초기화 | 같음 |
| 출력 | Sigmoid × 80 m | 상한만 다름 (공식 20 · 80) |
| 손실 | SiLog, λ 0.5, 정답 0.001–80 m인 픽셀 | 같음 |
| 최적화 | AdamW, 인코더 5e-6 · 헤드 5e-5, weight decay 0.01, 스텝마다 (1 − 진행)^0.9 | 같음 |
| 배치 · epoch | 16 · 10 | 다름 (GPU 1장) |
| 입력 크기 | 가로 · 세로를 14의 배수로 반올림 (256×640 → 252×644) | 다름 (공식 518 정사각 자르기) |
| 손실 해상도 | 예측을 정답 크기로 올려서 계산 (LiDAR 정답이 드물어 정답을 줄이지 않음) | 다름 |
| 정밀도 | bf16 자동 혼합 (`AMP=0`으로 끔) | 다름 |
| 고르는 모델 | 마지막 epoch. val은 epoch마다 재서 찍기만 한다 | — |

열화상 입력은 16비트 원시값을 사진마다 1–99 백분위로 잘라 0–1로 만든 뒤 세 채널로 복사한다(MS2 공식 벤치마크와 같은 처리). 값의 범위와 배율이 카메라마다 달라도 같은 입력이 된다.

`tone`의 증강은 사진마다 확률 0.8로 건다. 자르는 백분위를 U(0, 5)와 U(95, 100)에서 뽑고, 감마 2^U(−1, 1)을 건 뒤, 절반은 히스토그램 평활화 영상과 U(0, 1) 비율로 섞는다. 밝기 순서는 바뀌지 않는다.

## 데이터

원본(MS2 146 GiB, FIReStereo 29 GiB)에서 쓸 것만 골라 압축 없는 tar로 묶었다. 묶음은 이 저장소에 없고 받는 주소도 적지 않는다. 두 데이터 모두 다시 배포하면 안 되기 때문이다. 작업은 묶음을 두 곳에서 찾는다.

1. `/app/data` 아래에 올려 둔 사본 (크기와 sha256으로 찾으므로 이름과 폴더는 상관없다)
2. 없으면 실행 명령의 `LINKS=`로 받은 목록에 적힌 곳

어느 쪽이든 sha256이 `setup/data.json`과 같아야 쓴다.

| 파일 | 내용 | 장 수 | 크기 |
|---|---|---|---|
| `train.tar` | MS2 train 8 시퀀스, 3장마다 1장 | 25,516 | 5.35 GiB |
| `val.tar` | MS2 val 3 시퀀스, 3장마다 1장 | 4,750 | 1.03 GiB |
| `test_day.tar` · `test_night.tar` · `test_rainy.tar` | MS2 test 각 3 시퀀스, 10장마다 1장 | 2,332 · 2,292 · 2,503 | 0.51 · 0.48 · 0.48 GiB |
| `firestereo_test.tar` | FIReStereo 저자 test 폴더 5개 전부 | 5,021 | 2.53 GiB |
| `vivid.tar` | ViViD 야외 밤 2 시퀀스 · 낮 2 시퀀스 | 2,019 · 2,213 | 1.21 GiB |
| `smoke.tar` | 위에서 몇 장씩 (smoke용) | 120 | 32 MiB |

- MS2는 열화상 왼쪽 영상(256×640)과 열화상 시점의 `depth_filtered`만 넣었다. 솎는 규칙은 공식 로더와 같다(분할 목록 순서로 이은 프레임 줄의 `[0:-1:간격]`, val 3 · test 10). train만 공식 설정(전부)과 달리 3장마다 1장인데, 벤치마크 논문의 학습 장 수 26K와 맞는다. 평가 장 수는 선행 논문의 2.3K · 2.3K · 2.5K와 같다.
- FIReStereo는 드론에서 찍은 열화상(512×640)이고 숲과 건물 장면이다. Hawkins 4개 폴더는 낮(4,728장), Frick 1개 폴더는 비 오는 밤(293장)이다. 학습과 설정 고르기에 쓰지 않는다.
- ViViD는 손에 든 장비로 캠퍼스를 찍은 열화상(640×512)이고 정답은 LiDAR라 화면의 4 %쯤에만 있다. 선행 논문이 zero-shot을 잰 자료와 같은 것을 쓴다. ThermalSfMLearner-MS가 나눠 주는 후처리본에서 그 준비 스크립트와 같은 규칙(이동 속도 누적 0.15 초과)으로 프레임을 골랐다. 밤(`outdoor_robust_night1` · `night2`)이 선행 논문의 평가 세트이고 낮(`day1` · `day2`)은 참고로 잰다. 깊이 정답은 원본 npy를 16비트 PNG(1/256 m 단위)로 바꿔 담았다.
- 열화상 카메라의 초점거리는 387.8 px(MS2), 406.3 px(FIReStereo), 437.4 px(ViViD)다. MS2 대비 4.8 %, 12.8 % 다르다.
- 세 데이터를 쓰려면 각 데이터의 제공자에게서 직접 받아야 한다(MS2와 ViViD 후처리본은 설문 뒤 링크를 받는다). 이 저장소의 묶음은 그렇게 받은 원본에서 만든 것이고 실험이 끝나면 지운다.

## 판정 기준

결과를 보기 전에 고정한다(2026-11-16). 바꾸면 이유와 시각을 여기에 적는다.

- 2026-11-16 12:30 — 평가 세트에 ViViD 야외를 더했다. 선행 논문이 쓴 자료를 이날 받았기 때문이다. 이때까지 돌린 것은 smoke(3스텝)뿐이고 본 실험 결과는 없었다. FIReStereo 쪽 기준은 그대로다.

**평가 규칙.** 정답이 0.001–80 m인 픽셀만 쓰고 자르기는 없다. 예측을 정답 해상도로 올린 뒤 같은 범위로 자르고, 사진마다 지표를 구해 사진 평균을 낸다. 지표는 AbsRel · RMSE · δ1을 보고 주 지표는 AbsRel이다. 예측은 세 가지로 잰다.

| 이름 | 뜻 | 쓰임 |
|---|---|---|
| `raw` | 모델 출력 그대로 | 주 지표. MonoTher-Depth 공개 코드의 방식 |
| `median` | 사진마다 중앙값을 정답에 맞춤 | MS2 공식 벤치마크 코드의 방식. 벤치마크 표와 견줄 때 |
| `focal` | 학습 카메라와의 초점거리 비를 곱함 | `raw`의 치우침이 초점거리 때문인지 볼 때 |

ViViD만 정답의 테두리를 빼고 잰다. 선행 논문의 공개 코드가 그렇게 재기 때문이다. 변마다 40번째 줄에서 시작해 그 줄에 값 없는 픽셀이 40 %를 넘는 동안 안쪽으로 들어가고 100을 넘으면 멈춘다. ViViD는 정답이 드물어 사실상 가운데 [101:411, 101:539]만 쓰게 된다.

MS2 수치는 낮 · 밤 · 비 세 조건의 평균이다. 시드는 3개(0 · 1 · 2)이고 잡음 폭은 `base`의 시드 범위(최대 − 최소)로 잡는다.

**판정.**

| 판정 | 기준 |
|---|---|
| 기준선 재현 | `base`의 MS2 평균 raw AbsRel ≤ 0.085. 선행 표의 Depth Anything 미세조정 수치는 0.075인데, 모델 판(V1 → V2)과 학습 장 수가 달라 0.010의 폭을 둔다 |
| zero-shot 격차 | 대상(FIReStereo, ViViD 밤)마다 `base`의 raw AbsRel − MS2 평균 ≥ 0.05이면 '격차 있음'. 두 곳 모두 작으면 주제를 다시 본다 |
| `tone` 개선 | 대상마다 따로 본다. 그 대상의 raw AbsRel 차(`tone` − `base`)가 −잡음 폭보다 작고, MS2 평균이 잡음 폭보다 더 나빠지지 않을 때 |
| `tone` 차이 없음 | 그 대상의 차가 잡음 폭 안일 때 |

ViViD 밤의 선행 수치(MonoTher-Depth 표 III, raw)는 Depth Anything 미세조정 0.166 / 4.929 / 0.719, 그 논문의 방법 0.153 / 4.440 / 0.768이다. 견줘 보는 값이고 통과 기준은 아니다.

시드가 하나뿐인 팔은 판정하지 않는다.

## 실행

H200 요청 이슈의 실행 명령은 한 줄이다.

```bash
bash run.sh check LINKS=<값>                 # 1–2분. 환경 · 공간 · 외부 접속 · 묶음마다 받을 수 있는지. 설치 없음 (GPU 할당 1)
bash run.sh smoke LINKS=<값>                 # 작은 묶음으로 모든 단계를 끝까지. 스텝당 시간이 찍힌다 (GPU 할당 7)
bash run.sh all LINKS=<값>                   # 본 실험: base · tone × 시드 0 · 1 · 2 (GPU 할당 7)
bash run.sh all ARMS=base SEEDS=0 LINKS=<값> # 일부만
```

인자는 `KEY=값`으로 준다. `LINKS`는 묶음을 받을 곳의 목록을 가리키는 값으로, 저장소에 적지 않고 실행 명령에만 적는다. 화면에는 찍히지 않는다. `/app/data`에 묶음이 올라가 있으면 빼도 된다. `ARMS` · `SEEDS` · `EPOCHS` · `BS` · `AMP` · `CKPT` 등의 뜻은 `run.sh` 맨 위에 있다.

**결과는 화면에서 바로 읽을 수 있다.** 실행 하나(팔 × 시드)가 끝날 때마다 표와 판정을 다시 찍고, 화면은 끝 50줄을 늘 남기므로 이슈 댓글의 마지막 부분에 최신 표가 있다.

```

[eval base_s0] test_day 2,332 장 · raw AbsRel … RMSE … δ1 … · median … · focal AbsRel …
[표1] base  시드 3 | 낮 … | 밤 … | 비 … | 평균 …
[표3] base  | raw … | focal … | median …
```
